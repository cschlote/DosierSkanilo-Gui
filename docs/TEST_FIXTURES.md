# Test Fixtures

This note identifies the checked-in fixtures and generated datasets used by
the GUI and its DosierSkanilo backend. Most large GUI datasets are generated by
the tests in temporary directories; they are not separate checked-in files.

## GUI-generated test data

### Concurrent source queries

Test in `source/model/datasource.d`:
`repository tree and detail queries use independent concurrent connections`.
It generates a temporary repository with 80 root files and one nested file
(81 total), then checks concurrent tree and detail queries.

### JSON/SQLite query parity

Test in `source/model/datasource.d`:
`JSON and repository sources preserve filtered sorted navigation parity`.
It creates five files across a root and `album/`, scans to SQLite, exports JSON,
and checks filtered ordering and forward/backward navigation.

### Archive and torrent continuation

Test in `source/model/datasource.d`:
`archive and torrent detail adapters continue beyond 250 entries`. It generates
a temporary ZIP and torrent with 251 entries and checks bounded continuation
and the last entry path. The test requires the `zip` utility.

### Virtual table paging

Test in `source/ui/virtualblobtable.d`:
`Virtual blob model scrolls through evicted chunks in both directions`. It
imports a generated 1,000-row JSON catalog into SQLite, uses 50-row chunks,
and checks bidirectional reads, cache eviction, and the cache bound.

### Nested-entry selection and stale replies

Tests in `source/ui/nestedentrylogic.d` and `source/ui/nestedentrysignals.d`
use an in-memory nested-entry model with a page boundary at offset 250. They
check continuation offsets, later-page path copying, and stale-selection reply
rejection. The GTK signal test is opt-in and requires a display.

GTK opt-in checks and their commands are listed in
[`GUI-REDESIGN.md`](GUI-REDESIGN.md#verification-baseline). Tests create and
remove their temporary repositories themselves.

## Backend checked-in data fixtures

The backend's JSON compatibility and metadata fixtures live under
[`DosierSkanilo/test/`](https://github.com/cschlote/DosierSkanilo/tree/main/test):

- `json_file_v0.json` covers the unversioned legacy array, and
  `json_file_v1.json` covers a version-1 wrapper.
- `json_file_v2.json`, `json_file_v2_archive.json`, and
  `json_file_v2_torrent.json` are historical fixture filenames containing
  version-3 output; they are used as serializer expectations. There is no
  checked-in fixture whose wrapper actually declares `dataVersion: 2`.
- `json_file_v1_wrongversion.json` covers rejection of an unsupported wrapper
  version.
- `json_file_v2_archive.json` and `json_file_v2_torrent.json` cover archive and
  torrent serialization.
- `dummy-audio-file.mp3`, `dummy-video-file.mp4.mkv`, image/text/subtitle files,
  and torrent files provide small metadata/scanner inputs.

The serializer emits JSON version 3; there is no checked-in `json_file_v3.json`
fixture. The reader/writer behavior and the supported fixtures are described in
[`DATAFILE_EXTRACTION.md`](DATAFILE_EXTRACTION.md) and the backend
[`JSON-FORMAT.md`](https://github.com/cschlote/DosierSkanilo/blob/main/docs/JSON-FORMAT.md).
